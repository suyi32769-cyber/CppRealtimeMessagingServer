# 消息实验室使用说明

本界面运行在当前 Windows 电脑，通过 SSH 隧道访问服务器的两个本机 WebSocket 实例。网页与隧道只监听本机地址，不需要向公网开放 9001、9002 或网页端口。

## 启动

在项目目录双击 `启动可视化界面.cmd`。启动窗口会显示 `http://127.0.0.1:8765/`，并尝试打开浏览器；如果没有自动打开，可手动在浏览器输入该地址。保持启动窗口开启；按 Ctrl+C 可以停止本地网页和隧道。如果界面已经在运行，再次双击会打开已运行的页面。

此设备使用专用密钥目录 `F:\wp\realtime-frontend-key`。服务器为该公钥配置了端口转发限制，仅允许连接服务器本机的 9001、9002，不能打开 Shell。私钥留在本机，不应发送给他人或提交到 Git。服务器地址、密钥目录和端口在 `scripts/run-web.py` 中配置。

## 双实例体验

1. 打开第一个浏览器标签，选择 Alice 和实例 A，点击“连接服务”。
2. 输入房间 ID（例如 `room_001`），新房间点击“创建房间”，创建成功后会自动加入；已存在的房间点击“加入房间”。
3. 再打开一个相同地址的标签，选择 Bob 和实例 B，连接后加入相同房间。
4. 在任一标签发送消息，另一个标签应立即显示。点击消息下的“确认收到”可以观察 ACK 结果；“历史消息”可查询已保存的消息。

页面展示的连接和事件记录属于当前标签，不是服务器的全局监控。点击“退出房间”会移除该用户的持久化成员关系；仅关闭标签或断开连接不会主动退出房间。

“已确认”标记只保存在当前页面内；重新连接后历史接口不会返回逐条 ACK 状态，所以之前确认过的消息仍会显示“确认收到”。重复确认是安全的，服务器保存的确认进度不会因此丢失。

当前房间为演示用公开房间，拥有演示身份并知道房间 ID 的用户可以加入；演示令牌不能作为生产环境认证。

## 无法打开或连接时

- 确保服务器已经启动，Redis 和两个实例正在运行；它们目前不会随服务器重启自动启动。
- 本机需要 Python 3 和 Windows OpenSSH 客户端，并能连接服务器的 SSH 端口。
- 关闭其他占用本机 8765、19001、19002 的程序后重试。若只是关闭了浏览器标签，启动窗口仍在运行，可直接重新打开本地地址。
- 如果服务器公网 IP 或 SSH 主机密钥变更，需要更新启动器配置及可信主机记录后再连接，不应跳过主机密钥校验。
